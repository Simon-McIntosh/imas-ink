Draw long traces at display resolution

A trace sampled far finer than the figure's pixel width added file size and no visible detail: a 300,000-sample line rendered to a 324 KB SVG, and the altair renderer refused the same series outright at its data-transformer row ceiling. InkStyle (imas_ink/style.py) gains path_simplify_threshold (default 1.0) and trace_max_points (default 4000). render_to_bytes (imas_ink/io.py) now saves inside a matplotlib rc_context setting path.simplify True and path.simplify_threshold from the style, adding no other matplotlib code path; a caller may pass a style, defaulting to DEFAULT_STYLE. Altair has no equivalent simplification, so _render_timeseries_alt (imas_ink/alt.py) draws a series longer than trace_max_points through a min/max envelope in imas_ink/_decimate.py (_minmax_envelope): the samples are split into trace_max_points / 2 consecutive equal-count bins, each contributing its minimum and maximum in time order, so extremes and noise-band width survive while the emitted point count stays within the row ceiling; a series at or below the bound is drawn unchanged. Measure tests/unit/test_trace_resolution.py — three tests, all passing: a 300,000-sample TimeSeries through time_trace_figure_mpl and render_to_bytes(format="svg") yields an SVG under the 100 KB bound (51,648 bytes, stable across runs, as measured by the independent review; the 32,819 bytes the worker first quoted did not reproduce); the same series through _render_timeseries_alt emits 4,000 points (≤ trace_max_points) and still reaches the series' global minimum and maximum; a 500-sample series is drawn with all 500 samples. Negative control — with render_to_bytes ignoring path_simplify_threshold (matplotlib's default 0.111) the SVG is 324,979 bytes and test_long_trace_svg_is_bounded fails (negative-control.log, EXIT=1).
