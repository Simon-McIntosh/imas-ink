Drawing the vessel a machine description declares

Geometry Figure Vessel Units

imas-ink's poloidal geometry figure draws a wall's limiter units, coils and sensors, but not the vacuum vessel a wall IDS declares in description_2d.vessel. The JT-60SA machine description in imas-ambix now writes its vessel there, and the lead ruled on 2026-10-06 that the JT-60SA figures render through imas-ink with any missing drawing added to imas-ink (imas-ambix plan jt60sa-geometry-and-signal-figures, decision figure-owner). This plan adds that drawing.

§1 — Vessel skins in the 2D geometry figure

imas-ink already owns vessel extraction: extract_vessel_shells (imas_ink/three_d/walls.py) iterates wall.description_2d[0].vessel.unit and returns one VesselShell per unit, from an annular unit's centreline (with thickness offsetting it into a band) or from a plain outline. It does not read an annular unit's outline_inner and outline_outer, which is how the JT-60SA description writes its vessel: two closed 51-point skins, the same in both operating phases. This section extends that one owner rather than adding a second extractor: when an annular unit's outline_inner and outline_outer are filled, extract_vessel_shells returns one VesselShell for each, inner then outer, ahead of the centreline path, and leaves the centreline and outline paths unchanged.

The 2D pipeline then carries those shells. extract_geometry (imas_ink/extract.py) fills one new field on MachineGeometry (imas_ink/_types.py), typed with the existing VesselShell, from extract_vessel_shells; geometry_figure_mpl (imas_ink/figures.py) draws each shell as an unfilled line in the existing ink style beside the limiter units, and the viewport covers the shells. A new InkStyle constant is added only if the vessel needs a weight distinct from the wall. The 2D geometry has no vessel representation today, so the field retires nothing; it is the one public addition and reuses the type the 3D path already exports.

Done-when: a new test, tests/unit/test_vessel_units.py, builds a wall IDS with one limiter unit and one vessel unit whose annular outline_inner and outline_outer are filled, and asserts that extract_vessel_shells returns two closed shells and that geometry_figure_mpl adds both shells' lines to the axes; it fails when extract_vessel_shells ignores those outlines. uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests exits 0.

§2 — Compose two machine states into one figure

geometry_figure_mpl (imas_ink/figures.py) always makes its own figure with plt.subplots and draws every wall outline in one solid line, so a caller cannot place two machine states side by side on axes it lays out, nor overlay a second state as a reference. imas-ambix's JT-60SA figures need both: the OP1 and OP2 operating phases side by side on one viewport, and the two phases' wall and vessel overlaid on one panel. This section adds an optional ax argument to geometry_figure_mpl, which draws into the given axes and returns its figure instead of creating one, and one InkStyle constant, wall_linestyle (default solid), applied to the limiter outline and the vessel shells, so a caller draws a reference state with replace(DEFAULT_STYLE, wall_linestyle=DEFAULT_STYLE.ref_lcfs_linestyle), reusing the dashed reference vocabulary the style already carries rather than a new one. Nothing else changes: called without ax, the figure is drawn exactly as today.

Done-when: a test in tests/unit/test_vessel_units.py draws two geometries into two axes of one figure through the ax argument and asserts each axes holds its geometry's lines and no second figure was created, and draws one geometry with wall_linestyle="dashed" and asserts its wall and vessel lines are dashed; the existing geometry-figure tests pass unchanged; uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests exits 0.
