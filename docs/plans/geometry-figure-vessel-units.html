Drawing the vessel a machine description declares

Geometry Figure Vessel Units

imas-ink's poloidal geometry figure draws a wall's limiter units, coils and sensors, but not the vacuum vessel a wall IDS declares in description_2d.vessel. The JT-60SA machine description in imas-ambix now writes its vessel there, and the lead ruled on 2026-10-06 that the JT-60SA figures render through imas-ink with any missing drawing added to imas-ink (imas-ambix plan jt60sa-geometry-and-signal-figures, decision figure-owner). This plan adds that drawing.

§1 — Vessel skins in the 2D geometry figure

imas-ink already owns vessel extraction: extract_vessel_shells (imas_ink/three_d/walls.py) iterates wall.description_2d[0].vessel.unit and returns one VesselShell per unit, from an annular unit's centreline (with thickness offsetting it into a band) or from a plain outline. It does not read an annular unit's outline_inner and outline_outer, which is how the JT-60SA description writes its vessel: two closed 51-point skins, the same in both operating phases. This section extends that one owner rather than adding a second extractor: when an annular unit's outline_inner and outline_outer are filled, extract_vessel_shells returns one VesselShell for each, inner then outer, ahead of the centreline path, and leaves the centreline and outline paths unchanged. It also takes the description_2d entry to read, so extract_geometry passes the entry _select_description_2d (imas_ink/extract.py) chose for the limiter units and the vessel and the limiter always come from the same entry; called without one it keeps reading index 0, as the 3D path does today. The existing unit.outline fallback reads a field the Data Dictionary places on unit.element[*].outline; correcting it is outside this plan, which neither relies on nor changes that branch.

The 2D figure must not load the 3D stack, and importing anything under imas_ink.three_d loads that subpackage, which imas_ink/__init__.py keeps out of the eager import graph. So the vessel types and extractor move into core modules by role: WallOutline2D and VesselShell into imas_ink/_types.py beside MachineGeometry; extract_vessel_shells, which reads IDSs, into imas_ink/extract.py; and the pure-numpy _offset_polygon it uses into imas_ink/geometry.py beside close_polygon and points_in_polygon. The moved extractor reads thickness through the shared sentinel guard safe_float (imas_ink/_sentinel.py), and walls.py's private _safe_float, whose only caller was that extractor, is deleted (a separate copy in three_d/coilset.py is outside this plan). three_d/walls.py imports the types, the extractor and _offset_polygon (still used by synthesize_vessel_shell) from their new homes, and the lazy name map in imas_ink/__init__.py points VesselShell, WallOutline2D and extract_vessel_shells at _types.py and extract.py, so top-level access no longer loads three_d, the 3D path and its public names are unchanged, and each piece keeps one owner.

The 2D pipeline then carries those shells. extract_geometry (imas_ink/extract.py) fills one new field on MachineGeometry (imas_ink/_types.py), typed with the existing VesselShell, from extract_vessel_shells. Drawing goes through the component dispatch that owns 2D geometry, not a call of its own: the WallOutline component (imas_ink/components.py) gains the vessel shells beside its wall_units, and _render_wall_mpl (imas_ink/mpl.py) and _render_wall_alt (imas_ink/alt.py) draw them as unfilled lines in the wall's ink style. The altair renderer today plots only wall_r/wall_z and drops every limiter unit past the first, so it first gains the same loop over wall_units the matplotlib renderer already has, and the vessel shells join that loop in both, so geometry_figure_mpl and equilibrium_chart_alt both show the vessel by passing the shells to the WallOutline they already build, and the viewport covers the shells. The vessel is drawn with the wall's existing wall_color and wall_linewidth; no style constant is added. The 2D geometry has no vessel representation today, so the field retires nothing; it is the one public addition and reuses the type the 3D path already exports.

Done-when: a new test, tests/unit/test_vessel_units.py, builds a wall IDS with one limiter unit and one vessel unit whose annular outline_inner and outline_outer are filled, and asserts that extract_vessel_shells returns two closed shells, that a geometry whose richest description_2d entry is not index 0 takes its vessel from that entry, and that geometry_figure_mpl adds both shells' lines to the axes through render_mpl, with _render_wall_alt emitting a mark for every limiter unit and both shells, and that importing imas_ink.extract and imas_ink.figures leaves imas_ink.three_d out of sys.modules; it fails when extract_vessel_shells ignores those outlines. uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests exits 0.

§2 — Compose two machine states into one figure

geometry_figure_mpl (imas_ink/figures.py) always makes its own figure with plt.subplots and draws every wall outline in one solid line, so a caller cannot place two machine states side by side on axes it lays out, nor overlay a second state as a reference. imas-ambix's JT-60SA figures need both: the OP1 and OP2 operating phases side by side on one viewport, and the two phases' wall and vessel overlaid on one panel. This section adds an optional ax argument to geometry_figure_mpl, which draws into the given axes and returns its figure instead of creating one, and one InkStyle constant, wall_linestyle (default solid), applied by _render_wall_mpl and _render_wall_alt to the limiter outline and the vessel shells, so a caller draws a reference state with replace(DEFAULT_STYLE, wall_linestyle=DEFAULT_STYLE.ref_lcfs_linestyle), reusing the dashed reference vocabulary the style already carries rather than a new one. Nothing else changes: called without ax, the figure is drawn exactly as today. wall_linestyle retires nothing, because no style field sets the wall's line style today; it is this section's one public addition beside the ax argument.

Done-when: a test in tests/unit/test_vessel_units.py draws two geometries into two axes of one figure through the ax argument and asserts each axes holds its geometry's lines and no second figure was created, and draws one geometry with wall_linestyle="dashed" and asserts its wall and vessel lines are dashed; the existing geometry-figure tests pass unchanged; uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests exits 0.

§3 — Two traces on one panel

time_trace_figure_mpl (imas_ink/figures.py) draws exactly one TimeSeries per panel, and _render_timeseries_mpl (imas_ink/mpl.py) plots it in matplotlib's default colour cycle with no line-style control, so a caller cannot compare two channels on shared axes in the ink style. imas-ambix's JT-60SA signal figures need exactly that: each processed flux-loop channel against the raw channel of the same index. This section lets time_trace_figure_mpl take a panel as either one TimeSeries or a list of them drawn on the same axes through render_mpl, and adds one InkStyle constant, trace_linestyle (default solid), which _render_timeseries_mpl and _render_timeseries_alt (imas_ink/alt.py) apply; it retires nothing, because no style field sets a trace's line style today. _render_timeseries_mpl gains two keyword arguments, color (default none, meaning the colour cycle as today) and label_axes (default true), and time_trace_figure_mpl's panel loop uses them: the panel's first series is drawn exactly as a single series is today and owns the panel's y-label, units and time label; each later series is drawn with color set to the first line's colour and label_axes=False, so it adds a line in its own style's trace_linestyle and sets no label and no legend, and the panel's labelling never changes with the number of series. The two keywords stay on the private renderer: the panel loop calls _render_timeseries_mpl directly for the later series, so the public render_mpl signature does not change. A caller marks the second series with replace(DEFAULT_STYLE, trace_linestyle=DEFAULT_STYLE.ref_lcfs_linestyle). A panel given as a single TimeSeries is drawn exactly as today.

Done-when: a test in tests/unit/test_vessel_units.py builds a figure whose one panel holds two TimeSeries, asserts both lines are on that panel's axes with the second dashed and in the first line's colour, that the panel's y-label is the first series' and no legend was added, and that a single-series panel still draws one line; the existing trace-figure tests pass; uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests exits 0.
