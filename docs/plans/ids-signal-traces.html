Trace figures drawn from IDS

IDS Signal Traces

imas-ink draws only from IDS inputs, or from signals carrying standard-name metadata (lead ruling, 2026-10-07). Its geometry path already works this way: extract_geometry reads the wall, pf_active and magnetics IDS. Its only trace extractor, extract_time_traces, reads equilibrium global quantities. Nothing reads a pulse's measured signals, so imas-ambix's JT-60SA signal figures handed TimeSeries bare arrays. They took values from a signal-map view, plotted raw EDDB channels, and labelled them with strings the caller chose. This plan gives imas-ink the missing reader, so a caller hands over the IDS and imas-ink names the signal and its unit itself.

§1 — Read a dynamic signal's traces from its IDS

imas_ink/extract.py gains one public function, extract_signal_traces(ids, path), beside extract_time_traces, and exports it from imas_ink. It returns a list of TimeSeries, one per filled signal the path names. Here path is a data-dictionary path, relative to the IDS, to a signal node that carries data, such as coil/current in pf_active, or ip and flux_loop/flux in magnetics.

The path is unindexed, the same form imas-python's IDSMetadata.path gives for a node (it returns coil/current/data for a coil's current data). That is the data dictionary's own grammar, the one the imas-dd tools use, and it names a quantity rather than one instance of it. The function returns one series for every element of every struct array the path passes through. So coil/current yields every fed coil, and ip, itself a struct array in magnetics, yields every filled entry.

An instance path, as imas.util.get_full_path renders it (coil[0]/current), is not a second accepted form. A path holding [ raises ValueError naming the unindexed form, so a path copied from that helper fails loudly instead of returning a different set of series. To draw one element, the caller selects the series from the list by its y-label.

The function reads everything it returns from the IDS:

  • Values: the node's data.
  • Time base: the IDS's own time when ids_properties.homogeneous_time is 1, and the node's own time when it is 0. A value of 2 has no time base, so the call raises ValueError naming the path rather than guessing.
  • Unit: the data leaf's data-dictionary metadata (node.data.metadata.units, for example A or Wb).
  • y-label: the struct-array element's name when it has a non-empty one (a coil's CS1, a flux loop's FL1). Otherwise it is the path's leading component (ip).

No series carries a legend label. An element whose data is empty, such as an unfed coil or an unbound flux loop, is skipped rather than drawn as an empty panel. So the list holds exactly the signals the IDS carries.

The function scales, filters and resamples nothing. A unit, sign or channel conversion belongs to whatever wrote the IDS, never to the plotter. Display resolution remains render_to_bytes's concern. The result feeds the existing time_trace_figure_mpl unchanged: one panel per series, or several series on one panel. The section adds one public name and retires nothing. The TimeSeries type and the equilibrium extractor stay as they are.

Done-when: tests/unit/ink/test_signal_traces.py builds IDS in memory with imas.IDSFactory, with no file and no corpus data, and asserts the following.

  • A pf_active with three coils, one of them unfed, yields two series. Their y-labels are the coil names, their units are A, and their time is ids.time under homogeneous time 1.
  • A magnetics ip yields one series with y-label ip and unit A.
  • A magnetics under homogeneous time 0 takes each flux loop's own flux.time, with unit Wb.
  • Homogeneous time 2 raises ValueError.
  • The indexed path coil[0]/current raises ValueError.
  • No returned series carries a label.

The negative control reads time from ids.time regardless of homogeneous_time; the homogeneous-time-0 test must then fail. Two gates must add nothing against the base revision: uv run --no-sync pytest -p no:cacheprovider -q tests/unit adds no failure, and uv run --no-sync ruff check imas_ink tests adds no finding.
