§1 — The scene-cutaway tests patch the builder the composer calls

The five tests of TestRenderCutawaySynthetic in tests/unit/three_d/test_scene_cutaway.py patch imas_ink.three_d.scene._build_cutaway_static, which no longer exists. Commit f22fcc0 (2026-08-18) split it in two: _build_cutaway_geometry returns the clipped meshes and the first-wall outline, and _build_cutaway_overlay builds the flux overlay for one slice. render_cutaway_with_flux calls both. So four tests error at fixture setup with AttributeError, and test_no_wall_renders_without_overlay fails.

The tests are repaired to patch _build_cutaway_geometry, which keeps the (clipped_blocks, first_wall) return their fakes already produce. Each test keeps the behaviour it asserts. test_no_wall_renders_without_overlay still proves that a render whose geometry has no first wall draws no flux overlay, and if the overlay must now be observed through _build_cutaway_overlay, the test says so in its docstring. imas_ink/three_d/scene.py changes only if a repaired test exposes a real behaviour regression, in which case the manifest names the regression and the fix separately.

Done-when: uv run --no-sync pytest -p no:cacheprovider tests/unit/three_d/ exits 0 with all five TestRenderCutawaySynthetic tests passing, and the whole suite (uv run --no-sync pytest -p no:cacheprovider -q) reports no failure and no error. The negative control patches the old name again and turns the four fixture-based tests red with AttributeError.
