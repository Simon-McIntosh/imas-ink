Traces drawn at the resolution they are read

Trace Figure Display Resolution

imas-ambix's JT-60SA signal figures, rendered through time_trace_figure_mpl, came out at 1.7–3.4 MB per SVG because every one of up to 310,077 cached samples per trace is written as a path vertex, and every panel of the stack repeats the time-axis label. The lead ruled on 2026-10-06 that any drawing the figures lack is added to imas-ink (imas-ambix plan jt60sa-geometry-and-signal-figures, decision figure-owner) and that one SVG per figure suffices; this plan makes those SVGs small and uncluttered at the renderer.

§1 — Draw long traces through a min/max envelope

_render_timeseries_mpl (imas_ink/mpl.py) and _render_timeseries_alt (imas_ink/alt.py) plot every sample of a TimeSeries. A figure is read at a few thousand horizontal pixels, so a longer series adds file size and nothing a reader can see. This section adds one InkStyle constant, trace_max_points (default 4000), and draws a series longer than it through a min/max envelope: the samples are split into trace_max_points / 2 consecutive equal-count bins, and each bin contributes its minimum and maximum sample in time order, so the global extremes, every spike and the width of a noise band survive while the drawn path has at most trace_max_points vertices. A series at or below the limit is drawn exactly as today. The envelope is one private function in a private module, imas_ink/_decimate.py, because both renderers need it and neither may import the other's plotting library; it adds no public name, and trace_max_points retires nothing, because no style field bounds a trace's resolution today.

Done-when: a test in tests/unit/test_trace_resolution.py renders a 300,000-sample TimeSeries through time_trace_figure_mpl and asserts the drawn line has at most trace_max_points vertices and still reaches the series' global minimum and maximum, asserts a series shorter than the limit is drawn with all its samples, and asserts the altair renderer emits at most trace_max_points points for the long series; it fails when the envelope is bypassed. uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests adds no finding against it (the base carries 55).

§2 — Label a stacked trace figure's time axis once

_render_timeseries_mpl sets Time [s] as the x-label of every axes it draws, so time_trace_figure_mpl, whose panels share one time axis, repeats the label under every panel. This section has time_trace_figure_mpl clear the x-label of every panel but the bottom one after drawing, leaving the renderer unchanged so a single trace drawn through render_mpl keeps its label. It adds no public name.

Done-when: a test in tests/unit/test_trace_resolution.py builds a three-panel trace figure and asserts only the bottom axes carries the Time [s] x-label, and that a single series drawn through render_mpl still carries it; uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests adds no finding against it.
