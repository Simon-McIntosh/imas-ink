Traces drawn at the resolution they are read

Trace Figure Display Resolution

imas-ambix's JT-60SA signal figures, rendered through time_trace_figure_mpl, came out at 1.7–3.4 MB per SVG because every one of up to 310,077 cached samples per trace is written as a path vertex, and every panel of the stack repeats the time-axis label. The lead ruled on 2026-10-06 that any drawing the figures lack is added to imas-ink (imas-ambix plan jt60sa-geometry-and-signal-figures, decision figure-owner) and that one SVG per figure suffices; this plan makes those SVGs small and uncluttered at the renderer.

§1 — Draw long traces through a min/max envelope

_render_timeseries_mpl (imas_ink/mpl.py) and _render_timeseries_alt (imas_ink/alt.py) plot every sample of a TimeSeries. A figure is read at a few thousand horizontal pixels, so a longer series adds file size and nothing a reader can see. The two backends get the bound from different owners. Matplotlib already simplifies a path to display resolution when the figure is drawn, through rcParams["path.simplify_threshold"]: measured on a 300,000-sample line it gives about 8,900 vertices (232 KB of SVG) at the default 0.111 and about 1,050 (37 KB) at 1.0. Because the threshold is read when the figure is saved, the owner is imas-ink's save function, render_to_bytes (imas_ink/io.py), which saves under an rc_context setting path.simplify and a new InkStyle constant, path_simplify_threshold (default 1.0); no new matplotlib code path is added. Altair has no such simplification, and its default data transformer refuses a chart of more than 5,000 rows (MaxRowsError), so a long series cannot be drawn in altair at all today; _render_timeseries_alt therefore draws a series longer than a second constant, trace_max_points (default 4000, below that limit), through a min/max envelope: the samples are split into trace_max_points / 2 consecutive equal-count bins, each contributing its minimum and maximum in time order, so the extremes, spikes and noise-band width survive. The envelope is one private function in a private module, imas_ink/_decimate.py. The two constants retire nothing, because no style field bounds a figure's path resolution today, and the section adds no other public name.

Done-when: a test in tests/unit/test_trace_resolution.py renders a 300,000-sample TimeSeries through time_trace_figure_mpl and render_to_bytes(..., format="svg") and asserts the SVG is under 100 KB, asserts the altair renderer emits at most trace_max_points points for that series and still reaches its global minimum and maximum, and asserts a series shorter than the limit is drawn in altair with all its samples; it fails when render_to_bytes ignores path_simplify_threshold. uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests adds no finding against it (the base carries 55).

§2 — Label a stacked matplotlib figure's shared x-axis once

_render_timeseries_mpl sets Time [s] and _render_radialprofile_mpl sets ψ_norm as the x-label of every axes they draw, so both stacked builders, time_trace_figure_mpl and radial_profile_figure_mpl, whose panels share one x axis, repeat that label under every panel. The trace renderer already owns panel-label suppression through its private label_axes keyword, so this section extends that mechanism rather than clearing labels after drawing: both private renderers gain a private keyword, label_x (default true), that alone controls the x-label, and both builders pass label_x=False for every panel but the bottom one by calling the private renderer directly, as the trace builder already does for a panel's later series, so the exported render_mpl gains no keyword and a single trace or profile drawn through it keeps its label. The altair stack the MCP server builds in imas_ink/server/mcp.py repeats its time title too, but it is a served application outside the matplotlib figures this plan serves and is left unchanged. It adds no public name.

Done-when: a test in tests/unit/test_trace_resolution.py builds a three-panel trace figure and a three-panel radial-profile figure and asserts only each bottom axes carries its x-label, and that a single series drawn through render_mpl still carries it; uv run --no-sync pytest -p no:cacheprovider tests/unit adds no failure against the base revision, and uv run --no-sync ruff check imas_ink tests adds no finding against it.
